# 我的设备：免码连接自己的设备

状态：已实现（2026-11-20），代码位于 `internal/members`，接入见 `internal/backend/members.go`。本文的协议和验收场景适用于桌面端及仅作控制端的 Android。与第 8 节的差异：Android 使用 Keystore 保护的系统凭据库；桌面 worker 暂用用户配置目录内 0600 的 `member-keys` 文件，钥匙串、DPAPI 与 Secret Service 待接入。

## 1. 用户可依赖的行为

- 配对时需要本人在场。以后可以从任一成员发起连接，目标桌面须已开启“允许我的设备直连”。默认每次控制仍需目标桌面确认，用户可以在本机单独开启无人值守。
- 沿用现有 tailcat、公共或自建 DERP，无需账号、中心目录或常在线的组主机。刷新验证码、修改设备码不影响成员地址。换中继后的免码发现取决于是否仍有可达路径，见第 7 节。
- 任一有效成员都可添加、移除设备或轮换组密钥。移除在操作设备上立即生效，在其他设备上收到并持久化后生效。界面区分已确认和待同步的设备。
- 单台设备只加入一个组。临时协助继续使用设备码和验证码，支持旧客户端。成员协议单独协商版本。

## 2. 身份、寻址和信任起点

| 对象 | 定义与用途 |
| --- | --- |
| 设备身份 | 每次入组使用新生成的 Ed25519 密钥对。成员 ID 取公钥 SHA-256 的完整散列，界面可缩写，协议始终校验完整值。证书续期可以复用该公钥。 |
| 创组记录 | 包含协议版本、随机 32 字节组标识种子、创建者公钥、首把组密钥的指纹，由创建者自签。组 ID 是创组记录的完整记录 ID，首次配对时固定。创建者此后与其他成员平权，其退出或被移除不会改变组 ID。 |
| 组密钥 K | 每一代均独立随机生成 32 字节。成员用它推导 tailcat 节点私钥和预共享密钥。知道 K 的设备具备模拟该传输端点的材料，因此桌面数据、同步消息和新 K 都在内层双向 TLS 中传输。 |
| 密钥版本 | 创组时取创组记录 ID，此后取产生新 K 的变更记录 ID。记录同时承诺 K 的 SHA-256 指纹。同步、确认和密钥查找均使用完整版本 ID。 |
| 成员自述 | 每台设备签发自己的名称、平台、是否提供入站服务和中继候选地址。Android 发布“仅控制端”。自述只更新发现信息，成员资格由第 3 节决定。 |

为每个监听地址规范化中继描述：公共中继用区域编号，公共描述形如 `{"region":304}`，自建描述形如 `{"address":"derp.example.com:8443"}`。自建地址在发布前通过现有中继解析器校验并补齐端口，所有成员使用签名记录中的同一字符串推导。下式中各 ID 使用原始固定长度字节，中继描述使用规范 JSON 的 UTF-8 字节。组标识和密钥版本均已固定后才推导地址。

```text
seed = HKDF-SHA256(K, salt="remote-go/member-address/v1",
                  info=groupID ‖ keyVersion ‖ memberID ‖ relay, L=64)
nodePrivate = seed[0:32]        psk = seed[32:64]
ConnInfo = {nodePrivate.Public(), DiscoPublicForNode(nodePrivate), psk, relay}
```

把中继放入推导输入后，迁移期间新、旧监听器各有独立的节点身份。设备码入口仍沿用现有 Argon2id 推导。列表中的 ping 只说明传输端点可达，身份和可控制状态以成员连接结果为准。实现可复用 [现有 tailcat 地址和拨号逻辑](../../internal/tunnel/tunnel.go)。

## 3. 成员资格与历史合并

### 3.1 记录

v1 面向个人的小规模设备组，持久保存从创组起的签名历史。授权操作按单条历史依次生效。设备无需每次联络创建者，可以从本地已知的最新记录追加变更。

| 记录 | 必签字段与验证 |
| --- | --- |
| 创组 | 见第 2 节。接收设备校验配对时固定的创组记录 ID 和自签名。 |
| 成员变更 | 包含协议版本、组 ID、父记录 ID、签发成员 ID、操作和参数。每条只做一次添加、移除、轮换或“移除并轮换”。先重建父记录处的状态，再验证签发者当时有效、操作适用。 |
| 自述 | 包含协议版本、组 ID、成员 ID、单调递增序号、名称、能力和中继候选。仅采用当前有效成员自己的签名。并发同序号取记录 ID 字节序较大者。本机恢复写入前先追平已知序号。 |
| 确认 | 成员签名覆盖协议版本、组 ID、自己的 ID、已落盘的成员历史头和实际持有的密钥版本。接收方验证确认所指的历史和密钥版本相容。 |

各类记录用独立类型标签。签名字节为 UTF-8 类型前缀（`remote-go/members/v1/<type>` 加单个零字节）与记录体规范 JSON 的拼接，记录 ID 取这些字节的 SHA-256。签名置于记录体外。二进制字段使用无填充 Base64url，序号用十进制整数字符串（零或无前导零的正整数）。解析时拒绝重复键、未知类型、非法字段和越界值。跨平台测试固定签名字节、记录 ID、地址推导向量。[JSON 规范化见 RFC 8785](https://www.rfc-editor.org/rfc/rfc8785.html)。

添加记录绑定新公钥、派生的成员 ID 和该新身份签署的入组意愿（组 ID、邀请者 ID、一次性配对事务 ID）。同一身份在一条历史中只能加入一次。移除永久保留该 ID 的墓碑。原成员重新配对时生成新身份。被移除成员先前已写入共同历史的添加仍有效，移除界面列出它邀请的设备供本人核查。操作时间只供显示。

### 3.2 同步和分叉

1. 两端先核对组 ID，交换历史头。相同时只需比较自述和确认摘要。一方是另一方的祖先时，按父子顺序补齐、验证并原子提交缺失后缀。未知父记录先补取，单独一份成员名单或一个更大的计数不足以推进历史。
2. 若两端提供了从同一父记录出发、各自签名和授权均有效的不同子记录，则历史分叉。即使双方都把各自独立生成的 K 称为“下一代”，确认消息也只能对应其中一条具体的轮换记录。收到无效签名或任意伪造的历史头只拒绝该消息。只有验证完整的分叉证据才进入冲突状态。
3. 检测到分叉的设备持久保存两份证据，关闭现有成员会话，暂停成员控制、添加和发放 K。只允许与分叉共同前缀中有效、且在已知任一分支均未被撤销的成员交换签名历史和冲突证据。证据可以经这些成员继续传播。尚未同步的设备可能继续使用各自的本地历史。
4. v1 的冲突恢复由本人在一台在手设备上新建组，再用设备码逐一配对要保留的设备。每台恢复设备先在本机停用旧组，新组使用新的设备身份和 K。离线副本仍可能运行旧组，界面持续列出需要本地处理的设备。这个取舍避免按到达时间、链长或散列大小自动接受互相矛盾的授权。仅自述、收据或中继更新并发不会造成成员历史分叉。

每次配对、移除或轮换前尽力与可达成员同步，发送端提交后主动传播并在重连时重试。同一变更按记录 ID 去重。设备离线时仍可立即执行本地移除，界面提示待确认数及并发修改可能要求重新配对。

## 4. 配对与首次授权

配对使用已通过设备码和验证码认证的连接来发起。设备码端点在 `/api/info` 中返回 `"members": 1` 表示支持配对。发起者和入组者是两个独立角色。

| 发起连接的一侧 | 被连接的桌面 | 本次操作 |
| --- | --- | --- |
| 无组 | 无组 | 用户选择创建组，控制端创建并签发桌面入组记录。 |
| 已有组 | 无组 | 控制端邀请桌面加入。 |
| 无组（含 Android） | 已有组 | 桌面邀请正在连接的控制端加入。手机通过出站连接收取入组记录和 K。 |
| 同组 | 同组 | 验证双方已固定的身份后，可通过设备码路径补历史、密钥或中继信息。 |
| 不同组 | 不同组 | 显示两个组。用户须先在要迁移的设备上执行本地退出，再重新发起配对。 |

1. 用户在已认证会话选择配对。桌面为该会话创建短时、单次使用的随机事务令牌（32 字节），随原连接关闭或超时失效。配对使用设备码隧道内的独立 TCP 端口 7901 和 TLS 1.3。两端提供本次使用的身份公钥证书。新成员先在凭据库保存待配对私钥，已有成员使用已固定的身份。双方在本机记录同一个稳定的配对事务 ID。7901 只处理配对或恢复，独立于桌面消息处理器。TLS 建立后须提交有效令牌，每个令牌仅允许绑定一条连接。重新拨号须从已认证的设备码会话领取新令牌。
2. 首次相遇的身份在此连接上先处于待确认状态。双方就事务令牌、组 ID、双方公钥和邀请方向形成同一份规范 JSON 上下文，以 TLS exporter（标签 `EXPORTER-remote-go-pair-v1`，上下文为该 JSON 的 SHA-256）导出 8 字节，显示为四组四位十六进制。本人在两台设备上核对整串值并本地确认。一侧取消、断线、超时或内容变化即终止。界面同时显示组名或组指纹、设备名及同组成员可请求的控制权限。已有身份的同组恢复须额外核对原公钥。[Go TLS exporter 接口](https://pkg.go.dev/crypto/tls#ConnectionState.ExportKeyingMaterial)
3. 两端显示确认界面前先建立本机输入屏障：暂停本应用所有入站会话的远程输入，清除待发输入，释放已按下的键、鼠标按钮，再显示无默认允许动作的对话框。解除屏障前丢弃待处理事件。安全设置、退出/重建组、无人值守开关及成员控制确认使用相同本机授权边界。无法提供本机确认界面时拒绝。此机制假定设备操作系统及本地应用可信。
4. 双方确认后，新成员签发入组意愿。邀请者再次核对当前历史头，将添加记录和配对事务结果持久化，再经同一 TLS 连接发送完整签名历史、所需自述和当前 K。接收者验证组根、自己的添加记录和 K 指纹，落盘后返回签名确认。断线重试须携带原事务 ID、证明持有原私钥并重新完成本地核对。邀请者按已提交的记录补交，交付时使用当前历史和当前 K。若期间已被移除或发生分叉，则拒绝发放。邀请端显示“已添加，待对方确认”，直到收到确认或用户移除该成员。
5. 已加入与允许入站是两个设置。新桌面在本次配对界面可明确勾选“允许我的设备直连”，默认关闭。Android 始终只发起出站连接。

## 5. 成员连接与会话授权

成员节点在自己的 tailcat 网络内监听 TCP 7900，以 TLS 1.3 和双向证书认证承载后续 HTTP/WebSocket。设备码节点继续使用原有处理器。成员节点使用独立路由表和鉴权逻辑。backend 分别管理设备码监听器和成员监听器的生命周期，刷新验证码只重启前者。关闭全局“允许远程控制”同时停止两类入站及待确认请求。开启成员开关仍受全局设置约束。worker 排空检查和“断开全部”覆盖两个入口。[现有被控服务生命周期](../../internal/backend/backend.go)

- 两端要求对方证明持有证书对应的 Ed25519 私钥，将公钥映射到本组当前有效成员。拨号方还要匹配用户选定或发现流程指定的目标 ID。证书中的显示名称没有授权作用。使用 Go `crypto/tls` 完成密钥协商、握手验证和应用数据保护。v1 关闭成员连接的会话恢复，每次连接重新校验当前资格。[Go TLS 配置](https://pkg.go.dev/crypto/tls#Config)
- **同步**使用独立的 `/members/v1/sync`。只接受有界的签名历史、自述、确认及密钥交付消息，按批次传输并限制帧大小、未验证数据总量、并发和握手时间。设备打开列表、上线、发生本地变更时主动与可达成员同步，Android 在前台出站拉取。同步不会申请桌面权限、启动采集、注入输入或读写剪贴板。
- **控制**使用 `/members/v1/control`。双方先完成一次历史同步，再次检查本地资格与入站策略。需要确认时在目标桌面展示已认证设备名，30 秒内未在本地允许即关闭。通过后才登记桌面会话、初始化显示器并运行现有桌面协议。同步连接不能切换用途。仅观看设置对输入和剪贴板同样生效。现有 [host 会话入口](../../internal/host/host.go) 和 [client 拨号入口](../../internal/client/client.go) 均需把鉴权、等待确认与桌面收发分开。
- 运行时跟踪组 ID、成员 ID、连接用途和取消函数，覆盖 TLS 已建立、等待确认、活动桌面及同步连接。受同一个授权锁或状态代号保护的资格复查与会话登记可防止“刚移除又登记”。撤销、冲突或关闭入站时取消对应连接和待批准请求，停流、清理输入及剪贴板任务。若被撤销的是本机，停用整个组的监听、拨号和密钥分发。成员入口的握手限流独立于验证码的失败计数。
- 无人值守须由本人在目标桌面显式打开。命令行 `remote-go host -members` 可使用预先配对的本机身份。需要确认却无可用确认界面时，控制请求失败。GUI 以“无法联系设备”“身份不匹配”“等待同步”“被拒绝”等可验证状态说明失败原因。联网超时本身不能证明设备已被移除。

若目标尚未收到新成员的加入记录，会在 TLS 鉴权时拒绝该成员。邀请者可主动把记录同步给目标。新成员也可先联系双方都认识的成员代为传播。没有共同可达成员时，使用第 4 节的本地核对流程补齐签名历史，再重试成员连接。

## 6. 撤销、轮换与确认

**移除。** 本机选择目标，签发并持久化移除记录，撤销对应连接及发密钥资格，然后向可达成员传播。同步端在同一授权更新中使墓碑生效并取消该身份的所有连接。每台设备按有效成员的签名确认显示进度：确认的历史头包含该移除记录才算“已生效”。目标本身不计入待确认。旧成员表可能继续接受丢失设备，特别是离线设备刚恢复网络时。用户可在在手桌面先关掉成员入站，再同步。已交付给设备的数据和密钥无法远程收回。

**轮换。** 移除丢失设备时默认勾选“同时更换组密钥”。将移除对象与新 K 指纹写入同一条变更，其父记录承诺此前完整的成员和撤销历史。也允许单独轮换。已有成员通过已认证的专用同步或本地确认过的恢复连接接收新 K。首次入组按第 4 节交付。发送前双方先对齐成员历史，发送者在当前授权状态下重新核对接收者身份、本机资格、版本 ID 与指纹。撤销提交和密钥交付在本机串行裁决。接收端核验新 K 指纹并持久化后才签发确认。同步端总是先处理历史里的移除，再处理密钥。遇到分叉按第 3.2 节停止发放。

**旧地址过渡。** 启用入站的桌面在切换后以新地址提供服务，上一代地址只提供同步和追赶。旧地址上的原有控制会话结束并提示用新地址重连。每台桌面独立检查所有当前有效成员（含仅出站的 Android）是否都已签收具体密钥版本。全部签收或本机切换满 90 天即关闭旧地址并删除上一代 K。截止时间落盘，重启不延长。再发生轮换时只保留新的当前代和紧邻上一代，明确标出尚未追上的设备可能需要设备码恢复。

**恢复。** 落后多代、旧中继失效或过渡期已结束时，任一在手设备可用设备码连接一台在手桌面，按第 4 节同组恢复流程同步完整历史，验证双方身份仍有效且历史相容，直接交付当前 K。仍有效的设备保留原 ID。已移除设备须经新的本机授权，以新身份加入。本地判定分叉时执行重建组流程。

**退出。** 主动退出时先停用本机入站，在正常历史上签发对自身的移除并尽力传播，再清除本机身份和密钥。退出时若无可达成员，界面提示在另一台在手设备上移除这一身份。其他设备也可转发已签署的离组记录。冲突重建时从本机清除旧组密钥，不再向旧历史追加操作。

## 7. 中继迁移和设备列表

桌面切换中继时，先验证新中继并成功启动监听，再签发含新、旧候选的自述，新中继优先。旧中继仍可用时保留旧监听供同步，向可达成员推送自述。收到该自述或更高版本的**逐设备签名回执**后可提前结束迁移。提前关闭要求所有当前有效成员都已确认。最长保留 90 天，按本机首次迁移落盘时间计算。回执覆盖组 ID、签发人、目标成员 ID 和自述记录 ID。更高版本须明确包含同一新中继。连续改中继只保留最近两个候选。密钥轮换与中继迁移重叠时，用当前/上一代和新/旧中继的有限组合提供追赶，只有首选的新地址接受新控制请求。

旧中继已经不可达时，其他成员依次尝试已知候选，再向可达成员查询经目标签名的自述。仅有一台桌面和一部 Android，且手机只知道已经失效的旧中继时，没有自动发现新地址的路径。界面提示输入桌面当前设备码、验证码和必要的自建中继地址进行同组恢复。

列表显示有效成员、仅控制端、待同步撤销和密钥版本。限制并发探测并设置超时。已验证的连接才标记“身份已确认”，P2P/DERP 路径取当前连接的测量结果。仅控制端显示最近同步时间，无“连接”按钮。

## 8. 本地存储与在线更新

| 位置 | 内容 |
| --- | --- |
| 系统凭据库 | 本机 Ed25519 私钥、按组 ID 与版本 ID 分槽的当前及过渡 K。macOS 使用钥匙串，Windows 使用 DPAPI，Android 用 Keystore 包装密钥，Linux 优先使用 Secret Service，缺失时使用私有目录内的 0600 文件。 |
| 用户配置目录的 `members.json` | 固定的创组记录、完整签名历史、自述、确认、冲突证据、配对事务结果、当前密钥槽引用、迁移截止时间和成员访问策略。缺失或无法验证的授权状态按关闭入站处理。 |
| `app.json` | 现有应用设置。成员访问策略与成员状态一起提交，避免两处配置同时决定授权。 |

同一配置目录只允许一个成员状态写入者。桌面提供服务时由持有操作系统独占锁的 worker 写入，GUI 与会话窗口经本机受限 IPC 提交操作和读取快照。独立 CLI 或 Android 在没有 worker 时取得同一所有权后写入。命令由写入者串行执行，校验预期历史头。重复事务返回原结果。在线更新时旧 worker 完成或拒绝待办、停止成员入口并交还锁，新 worker 取得锁、重新验证状态后才接受连接。旧版 worker 无协议能力时禁用成员操作，等它排空后切换。[现有在线更新服务](../../internal/liveupdate/service.go)

提交顺序为先创建新凭据槽并校验读取，再写临时状态文件、刷盘、原子替换并确保持久化，最后公布新状态、发送确认并清理无引用的旧槽。授权变更在持久化和运行时取消之间阻止其他成员操作获准。启动时只信任状态已引用且指纹匹配的槽。清理孤立的新槽，缺槽或不匹配时暂停涉及密钥的服务并提示恢复。单写者和原子替换用于处理并发与崩溃。单条记录签名不能发现整份本地状态被恢复到一个旧的有效快照。备份还原后应先经在手成员核对最新历史，再开启入站。本机系统或凭据库已被控制超出此设计的保护范围。

## 9. 安全边界

| 情况 | 用户可以依赖的保护和限制 |
| --- | --- |
| DERP 或持有旧 K 的设备 | 中继可观察流量元数据。知道旧 K 及原寻址信息的设备在过渡期仍能探测旧地址。桌面内容、历史同步和新 K 由内层 TLS 保护。 |
| 设备已丢失，其他成员尚未收到撤销 | 仍持有有效私钥的设备可以行使本地成员表赋予的权限。目标桌面的默认本地确认保护控制入口。确认界面不能代替撤销传播。 |
| 已授权成员故意制造冲突 | 平权允许成员移除他人或签发竞争变更，可能造成服务中断。在手设备可以关闭入站并重建组，用户需重新确认保留设备。 |
| 本机其他程序可以模拟输入或读凭据 | 配对确认只约束 Remote Go 自己的输入通道。已受控制的操作系统、用户账户或可读的私钥须按设备丢失处理。 |

## 10. 实施顺序与验收

1. **内部原型。** 在 `internal/members` 固定记录格式、验证规则、密钥存储接口与测试向量，扩展 `internal/tunnel` 的成员地址和双向 TLS。在两台桌面上打通本机配对和仅同步模式。
2. **首个可发布版本。** 接入 `internal/host`、`internal/client`、`internal/backend`、GUI、Android 与 worker。配对、撤销、按身份断开、传播回执、轮换与恢复作为同一协议版本交付。无人值守在相应用例通过后开放。旧版本之间及新旧混用的设备码连接继续走原流程，旧端不显示配对入口。

| 验收场景 | 预期结果 |
| --- | --- |
| 只持有 K。拨 B 却收到有效成员 C 的证书。已撤销客户端请求新 K | 第一种双向 TLS 失败，第二种在发送控制请求前终止，第三种在已应用撤销的成员上被拒绝。 |
| 首次配对核对值不同、远程输入尚在队列、弹窗超时、确认前断线 | 没有新增授权，没有 K 交付。所有本应用远程输入均无法替本人确认。 |
| 桌面邀请新 Android，或 Android 建组后邀请桌面。添加提交后回执丢失 | 两种方向均可完成。同一事务重试产生一条添加记录。已撤销身份重试失败。 |
| 打开列表同步。默认确认、仅观看或无人值守的控制连接 | 同步期间没有采集和剪贴板任务。控制批准前无桌面数据。仅观看全程禁用输入和剪贴板。 |
| C 与 A 失联但仍与 B 连通，A 移除 B 时 C 上有 B 的会话或待确认请求 | A 显示 C 待同步。C 提交墓碑时立即取消 B 的活动及待批准连接，回执使 A 的进度更新。 |
| 被移除者发来指向旧父记录的添加。两个成员从相同父记录各自轮换 | 无效记录被丢弃。两条有效但冲突的历史触发持久化冲突状态。不会凭相同代数确认、放行控制或发放密钥。 |
| Android 跨两次轮换才上线，或桌面迁移后旧自建中继已下线 | 有共同已知路径时追赶。只有失效地址时提示设备码恢复，恢复后验证原组、原身份和当前 K。 |
| GUI 撤销与 worker 更新自述并发，进程在写入新槽或替换文件后崩溃 | 重启后保留最后完整提交的墓碑。不会使用未提交的密钥、签发虚假确认或同时启动两个写入者。 |
| 有成员等待本地批准时关闭全局“允许远程控制” | 两类入站均关闭，迟到的批准无效。 |
| 新客户端连接旧桌面，或设备码改动时已有成员连接 | 临时协助正常。旧端无配对选项。单独修改设备码或验证码不打断成员监听。 |
